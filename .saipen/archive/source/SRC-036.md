AUDAPACK ↔ SAIPEN AUDIT LIFECYCLE ALIGNMENT

Do NOT change SAIPEN's audit deletion policy.

Current SAIPEN v7.253.0 already implements the desired behavior:
a proven-closed audit generation is automatically consumed/deleted on the next
`cc`, through the hash-guarded journaled `audit_inbox.consume` operation.

The problem is producer/integration drift in AUDAPACK.

FIX AUDAPACK:

1. For SAIPEN-managed projects, stop allocating audit/N.md locally with:
       max(existing) + 1

2. Deliver captured audit bytes through the canonical SAIPEN producer API:
       saipen audit enqueue
         --producer audapack
         --operation-id <stable capture UUID>
         [--item-id <finding/capture id>]
         --file <captured body>

3. SAIPEN owns:
       - layer allocation
       - monotonic IDs
       - audit/N.md publication
       - binding
       - generation identity
       - later consume/delete

4. AUDAPACK owns:
       - capture
       - project selection
       - display
       - producer operation identity
       - refresh

5. Change every generated continuation command from:
       saipen cc "<audit path>"

   to:
       saipen cc

   or UI shorthand:
       cc

6. Do not use:
       saipen gg "<audit path>"

   as Audit Inbox ingestion.

7. Keep manual Delete in AUDAPACK only as an explicit operator action.
   Normal successfully implemented layers must disappear through SAIPEN consume,
   not AUDAPACK manual deletion.

8. Refresh the Layers view after enqueue / cc-visible lifecycle changes so
   consumed files naturally disappear from the UI.

9. Optional but useful:
   show SAIPEN transport state beside each layer where available:
       NEW
       ACTIVE
       BLOCKED
       CLOSED_PENDING_DELETE

   Do not invent state when no binding exists.

10. Regression:

   enqueue capture A
       -> SAIPEN allocates audit/N.md

   bare cc
       -> captures generation and creates Source/Work

   incomplete Work
       -> layer remains

   model merely claims "done"
       -> layer remains

   Source CLOSED + Work DONE + exact same bytes
       -> next cc consumes layer

   bytes changed after closure
       -> old cleanup refuses
       -> changed file becomes NEW generation

   foreign audit/notes.md
       -> never deleted

   two concurrent AUDAPACK producers
       -> allocator gives distinct monotonically increasing layer IDs

Goal:
INAUDIT Layers is a live work queue, not permanent history.
Closed proven layers disappear automatically.
No deletion decision depends on model confidence.
