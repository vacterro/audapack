## TARGET R — NO UNEXPLAINED INTERNAL IDLE GAPS

For every stage transition:

if the prerequisite condition is already true,
continue immediately.

Do not add fixed sleeps merely for "stability".

A wait is legitimate only when waiting for an observable condition or an external operation.

Every internal gap materially above normal event-loop scheduling must have a named reason.

Examples of legitimate waits:

* Bridge request in flight;
* archive packing;
* file download;
* ChatGPT attachment registration;
* ChatGPT Send disabled;
* navigation/route not yet committed;
* positive Send acceptance still pending.

Examples of illegitimate waits:

* fixed 500 ms because it historically seemed safer;
* retry timer still armed after a positive condition became true;
* waiting for a timeout after MutationObserver already proved readiness;
* sleeping before checking a state that is already available.
