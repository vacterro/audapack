AUDAPACK
SAIHANDOFF APPEND  RESTORE PER-LAUNCHER TERMINAL IDENTITY COLORS

NEW USER-OBSERVED REGRESSION

Terminals launched from AUDAPACK have lost the distinct console color identity
that previously belonged to each launcher/agent.

Visual evidence:
multiple AUDAPACK-launched agent consoles now render with the same default
PowerShell/console palette instead of their established individual launcher
colors.

This is not merely decorative.

AUDAPACK is explicitly a multi-agent launcher and the operator uses visual
launcher identity to distinguish concurrently running agent terminals.

Treat this as a separate ticket after the currently active T-240 reaches a
clean checkpoint.

Do not fold this into unrelated SAIHANDOFF/widget work.

======================================================================

======================================================================

preservation.

Inspect at minimum:

audapack/ui_qt/main_window.py

audapack/config.py

_launch_degraded_opencode()

_on_open_with_codex()

Current structural observation:

1. Legacy unmanaged OpenCode/Cline may invoke:

V:\___VAC\__K\__CUSTOMIZATION\___CONTEXTMENU\Scripts\AI_AGENT_LAUNCHER.PS1

2. Managed SAIPEN OpenCode intentionally bypasses that external launcher.

3. Codex accounts launch through direct PowerShell.

4. FreeBuff launches through direct PowerShell.

5. Claude / Antigravity / ZCode shared CLI launchers use direct PowerShell.

6. LauncherConfig currently has no durable console-style/color identity.

7. Direct launch paths do not restore the established per-launcher console
   colors.

Therefore multiple launcher identities inherit the same default PowerShell
console palette.
